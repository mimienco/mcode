## Security pass

### 1. Command ACL surface

**Resolved grants verified against build output** (`src-tauri/gen/schemas/capabilities.json` + `acl-manifests.json`, regenerated by `tauri-build`):

- Four capability files, all scoped `windows: ["main"]` (`src-tauri/capabilities/main.json:5`, `ssh-commands.json:5`, `pty-commands.json:5`, `fs-commands.json:5`). No remote-URL windows exist (`tauri.conf.json:18` `windows: []`; the single `main` window is built in `lib.rs` with `WebviewUrl::App`). Good.
- No broad plugin grants: only `core:default` and `notification:default` preconfigured sets; window mutation is granted per-op (`allow-close`, `allow-minimize`, `allow-toggle-maximize` — `main.json:9-11`). No `fs:default`, no `shell:*`, no `dialog:*`, no global HTTP scope. Good — least-privilege held.
- Every `fs_*`, `pty_*`, `ssh_*` command is granted explicitly with "no default grants" descriptions. Command names resolve through `rename_as` correctly (verified: `allow-ui-speech-feed-audio` → allows `ui_speech_feed_audio` in the ACL manifest).
- **Gap (S4):** `ui_export_html_to_pdf` is in `invoke_handler` (`lib.rs:657`, imported at `lib.rs:49`) but appears in **no** capability file. Resolved-ACL check confirms it is the only app command with zero grants. The command's contract (`export_commands.rs:36-49`) is to return a structured `{success:false,error}` object; instead every renderer invoke is rejected by the ACL with a permission error, so the renderer's error handling of the export path can never engage. No security impact (fail-closed); it is a wiring defect.
- Filesystem/process work with renderer-controlled paths: every `fs_*` command authorizes through `FsScopeRegistry::authorize` before touching disk (`filesystem_commands.rs:364-366` read_dir, `:383-385` read/write, `:424-427` atomic write, `:480-483`, `:500-503`, `:524-528` copy both legs, `:549-553` rename both legs, `:570-573` delete, `:600-602` search root, `:635-637` replace root, `:705-707` watch). The registry canonicalizes parents, preserves symlink leaves under `LeafPolicy::Preserve` (probe **before** canonicalize so the link target never leaks), canonicalizes nearest existing ancestor for missing leaves, and fails closed on cross-drive containment (`crates/mcode-fs/src/scope.rs:399-472`). This matches the `command_error` validation discipline of `pty_commands.rs` and exceeds it. Clean.
- `pty_spawn` accepts renderer-controlled `program`/`args`/`cwd` **by design** (it is a terminal app); the surface is argv-vector only (never a shell string — `crates/mcode-pty/src/pty.rs:26-28`), validates non-empty program (`pty.rs:41-46`), and scrubs inherited env through `mcode-process`'s policy (`pty.rs:101-123`, tested for `MCODE_PANE_KEY` at `:192-225`). Documented-by-design surface; no change requested.

### 2. Path traversal

- **Speech models (clean):** `model_id` from the renderer is matched against the **static** catalog before any path is built — `VoiceState::catalog_entry` (`speech_commands.rs:117-120`), `model_dir` = `models_root.join(model_id)` only for catalog hits (`:122-126`). Catalog ids are compile-time identifiers with no separators (`catalog.rs:30-58`), so `../` cannot escape. Download files write `<model_dir>/<file.name>` with `file.name` also from the static catalog (`download.rs:124-125`). The recognizer loads only from the same resolved dir (`speech_commands.rs:694-701`). No renderer-controlled path component survives.
  - `MCODE_MODELS_DIR` env override (`speech_commands.rs:148-150`) is process-level, not renderer-reachable. Fine.
  - The ASCII ProgramData mirror (`session.rs:27-45`) is keyed by `sha256(requested)[..8]` hex — no traversal component. Fine.
- **`app_dialogs.rs` (clean):** both pickers return `std::fs::canonicalize`d absolute paths (`app_dialogs.rs:45-52`) of **user-chosen** dialog results; the app-owned default dir is only the dialog start point (`:36-43`). The renderer receives a canonical path but never passes one *in* — there is no renderer-controlled path input on this surface at all.
- **`terminal_preview.rs` pty ids (clean with a note):** `terminal_preview_input`/`fit` parse the renderer's `pty_id` string to `u64` and fail with `invalid pty id` before any state lookup (`terminal_preview.rs:240-247,255-262`), mirroring `parse_pty_id` in `pty_commands.rs:224-235`. `terminal_preview_connect`/`ack`/`unsubscribe` operate on preview-connection state keyed by the raw string (S7 note below) — they never touch a PTY.

### 3. Injection

- **`open-system-settings` (clean):** `cmd /C start "" ms-settings:notifications` is built from **constant** args only (`notification_commands.rs:78-83`); no renderer input reaches the command line, `CREATE_NO_WINDOW` set. Equivalent to the Electron `shell.openExternal('ms-settings:notifications')` (`src/main/ipc/notification-system-settings-link.ts:16-18`). No injection surface.
- **`test_local_network_connection` (S2):** `host`/`port` are renderer-controlled and concatenated into `format!("{host}:{port}")` for `TcpStream::connect` (`os_permissions.rs:165-166`). That is **not** shell injection (no process spawn; tokio parses host:port), but see S2: the Electron port kept the *classification* gate only as a discarded `let _ =` (`:172`).
- **Download URL construction (clean statically, S1 is a correctness bug):** URLs are `format!` over **static** catalog fields only (`catalog.rs:22-27`) — repo/revision/name are compile-time constants, renderer can only pick an id that must match the catalog (`speech_commands.rs:551-555`). No SSRF/injection: scheme pinned `https:`, host pinned `huggingface.co`. The doubled-repo format bug (S1) breaks the download, not the sandbox.

### 4. Deep link (`skill_share_deep_link.rs`)

Gate (`:16-31`): strip `mcode://` → strip `skills/share/` → trim trailing `/` → `[A-Za-z0-9_-]{1,128}`.

- **No bypass:** percent-encoding (`%2e%2e`), path segments (`a/b`), dots, and whitespace all fail the charset test; the id is later only stored/echoed to the renderer as an opaque string (`:56-63`) and consumed one-shot — it never joins a path or command on the Rust side. The Electron `mcode:` branch (`src/shared/skill-share-link.ts:14-17`) enforces the identical charset via regex.
- **Parity asymmetries (S8, fail-closed both ways):**
  - Scheme case: WHATWG `new URL('MCODE://skills/share/x').protocol === 'mcode:'` (lowercased), so Electron accepts uppercase-scheme links; the Rust `strip_prefix("mcode://")` is byte-exact and rejects them.
  - Host prefix: Electron matches `${url.host}${url.pathname}` and also accepts the `https://app.mcode.dev|share.mcode.dev` web-link branch; the Rust gate serves only the OS-registered `mcode` scheme (`tauri.conf.json:31-34`), which is the correct v1 scope (the https branch belongs to the renderer paste box, which still uses the unchanged TS `parseSkillShareId`).
  - Both asymmetries reject links Electron would accept — a compat gap, not a security one.

### 5. Clipboard (`clipboard_commands.rs`)

- Read cap: `max_bytes` defaults to 16 MiB (`:29-31`), but enforcement happens **after** `arboard`'s `get_text()` has already allocated the full string (`:33-37`) — answer to the pre/post question: **post-allocation**. This is inherent to arboard (no bounded-read API) and the OS clipboard itself bounds the payload; the cap is the renderer's too-large error contract (mirrors `CLIPBOARD_TEXT_READ_MAX_BYTES`, `tauri-clipboard-client.ts:19-21`), not a memory-safety boundary. Renderer-controlled `max_bytes` can only *raise* the cap — accepted-by-design for parity with the Electron preload, which passed the same option.
- Write caps (`:49-51,68-70`) are checked **pre**-spawn-blocking on the already-materialized `String`, so a 2 GB invoke payload is refused before the clipboard task runs — but note the IPC layer has already deserialized it (same tradeoff as every Tauri command; see S5).
- `writeTerminalText` re-reads and byte-compares (`:73-86`) — correct verification, no partial-failure false success.

### 6. CSP (`tauri.conf.json:14`)

```
default-src 'self'; connect-src 'self' ipc: http://ipc.localhost;
font-src 'self' data:; img-src 'self' asset: data: blob:;
object-src 'none'; script-src 'self' 'wasm-unsafe-eval';
style-src 'self' 'unsafe-inline'; worker-src 'self' blob:
```

- `script-src 'wasm-unsafe-eval'` — **needed and minimal**: VSCode's oniguruma wasm (regex engine) requires `WebAssembly.instantiate`; this is the accepted alternative to `unsafe-eval`. Keep.
- `connect-src 'self' ipc: http://ipc.localhost` — the Tauri v2 IPC transport (Windows uses `http://ipc.localhost`). No wildcard hosts; all renderer fetch/XHR to arbitrary hosts stays **blocked** (which is what makes S2 the only network-probe escape hatch — fixing S2 closes it).
- `img-src asset: blob: data:` — `asset:` is the `convertFileSrc` protocol (required for any local-file imagery, e.g. picked markdown/workspace assets); `blob:`/`data:` for canvas/inline images. Scoped to images only. OK.
- `worker-src 'self' blob:` — required for wasm workers instantiated from blobs (oniguruma pattern). OK.
- `style-src 'unsafe-inline'` — the one weakening; Tauri/wry injects inline styles into the webview and the app's CSS-in-JS needs it. Standard Tauri posture, retained as a NOTE.
- `object-src 'none'`, no `frame-src`. `media-src` is not needed yet (notification sound playback is not ported; when it lands as file playback it will need `media-src 'self' asset:` — flagged for the sound slice).

### 7. Secrets

- **`authToken` in `runtime_metadata` (S3):** the module doc claims "user-scoped ACL on Windows, 0600 on POSIX" (`runtime_metadata.rs:12-14`), but `write_atomic` (`:90-108`) does a plain `std::fs::write` + rename with **no** permission step. The TS original routes through `writeSecureJsonFile` → `src/shared/secure-file.ts` (`chmodSync 0o600` on POSIX + `restrictWindowsPathSync` ACL hardening on Windows; the original asserts mode `0o600` in `runtime-metadata.test.ts:168,196`). The Rust port therefore writes the CLI auth token with the process-default ACL — readable by other local principals in multi-user scenarios. Memory hygiene for the in-process token (no zeroize) is accepted per batch scope; the **file** is the gap.
- **E2EE keys in `mcode-wire` (S10):** `BoxKeyPair.secret_key: [u8; 32]` and `derive_shared_key`'s returned `[u8; 32]` are plain copies with no `zeroize` (no `zeroize` dep in any workspace crate). Keys never touch disk (pairing offers carry public keys only — `pairing.rs:35-37`), lifetimes are session-scoped. Best-effort note per batch instruction, not a blocker; suggest `zeroize::ZeroizeOnDrop` on the pair/shared-key newtypes when touched next.
- Token values never appear in logs or error strings (grep of `src-tauri` error formatting: messages carry codes/paths only); speech transcripts emit to renderer events, not stderr.

## Performance pass

### a. `feedAudio` hot path (S5)

- Transport: `Array.from(samples)` boxes every sample into a JS number, then Tauri's invoke JSON-stringifies it. For a 100 ms chunk at 16 kHz mono (1 600 f32):
  - binary-f32 wire: 6.4 KB (Float32Array → ArrayBuffer)
  - JSON path: ~1 600 × up-to-23-char floats ≈ **15-25 KB** string + parse to `serde_json` `Vec<f32>` (an owned heap `Vec` per call, `speech_commands.rs:672`) ≈ **3-4× the payload in JS + a second full copy in Rust**, at ~10-20 chunks/s → roughly **0.15-0.5 MB/s** of JSON churn per dictating session. Survivable, but ~40-80× the necessary bytes.
- No cap exists before deserialization: a buggy/compromised renderer loop invoking with a 10⁸-element array forces the IPC layer to allocate it before the ring's 30 s cap (`speech_commands.rs:199-207`) ever applies (the cap bounds *retention*, not *ingestion*).
- **Fix (already flagged in code, `tauri-speech-client.ts:130-133`):** switch to `tauri::ipc::Channel` or a raw-ArrayBuffer invoke body with little-endian `f32` decoding in `ui_speech_feed_audio`; while there, add an ingest cap (e.g. reject `samples.len() > RING_MAX_SAMPLES`) before allocation.

### b. Terminal-preview ring (S7)

- Eviction is `self.entries.remove(0)` + `self.chunks.remove(0)` per evicted chunk (`terminal_preview.rs:87-88`) — O(n) memmove per eviction.
- At the 256 KiB cap with the forwarder's ≤64 KiB batches (`:36-42`), the ring holds ≤4-8 entries → effectively O(1) in practice. Worst case (1-byte chunks, e.g. a pathological slow-consumer stream) is 262 144 entries and O(cap²) cumulative shift — not reachable through the current 2 ms-gated forwarder batching.
- Adjacent: `terminal_preview_connect` creates a `PreviewConnection` for **any** string pty id (`:177-179`, `entry().or_insert_with`) without checking PTY existence (input/fit do, `:240-247`). A renderer loop can grow the connection map until unsubscribe. Renderer-DoS only.
- Verdict: acceptable as shipped; if the forwarder ever pushes sub-KiB chunks at high rate, switch to `VecDeque` or a head-index ring.

### c. Download double hash (P1)

- `download_file` maintains a streaming `Sha256` (`download.rs:134`, updated at `:143` and `:171`) whose result is **never read** — the verdict comes exclusively from `hash_file(&part_path)`, a full re-read of the finalized `.part` (`:197`, `:214-226`). Every downloaded byte is SHA-256'd twice and read twice (network→disk hash + disk→hash pass).
- Quantified: the largest catalog file is 652 MB (`catalog.rs:37-40`); at a typical ~1.5-2 GB/s SHA-256 + page-cache-warm read this adds **~0.7-1 s per file** and doubles I/O; the cache churn also evicts ~650 MB that the next file's download could have used.
- Worse, the resume path (`:140-145`) `read_to_end`s the **entire existing `.part` into a `Vec<u8>`** (up to hundreds of MB of RAM) just to hash a prefix that `hash_file` re-covers anyway.
- **Minimal fix (pure deletion):** drop the `hasher` field and both `hasher.update` calls; replace the resume block with `downloaded = std::fs::metadata(&part_path)?.len();`. `hash_file` remains the single source of truth (it already covers the pre-existing prefix — its own comment says so, `:195-196`).

### d. Renderer shim hot paths (clean)

- `createDesktopInvoke` (`desktop-client.ts:91-99`) adds one `try/catch` + an error-normalization branch that only executes on failure — zero happy-path cost.
- `pty-client.ts` adds `String(id)` per call and `stripNullContextFields` **only on error** (`:104-112`) — negligible; keystroke writes stay 1:1 (`{id, data}`).
- `fs-client.ts` methods are direct arg-shape passthroughs (`:135-165`); no copying, no per-call allocation beyond the args object.
- The speech shim's `onDownloadProgress` recomputes a division per event (`tauri-speech-shim.ts:247-252`) — event-rate, not hot-path. No per-call overhead worth changing.
- One shim-behavior note: `makeStopMarksStopped` monkey-patches `client.stopDictation` per subscriber (`tauri-speech-shim.ts:140-152`) — fine at this call rate; just avoid stacking subscribers (unlisten restores the original, so it self-heals).
